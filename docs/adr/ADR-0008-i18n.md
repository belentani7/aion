# ADR-0008: Internationalization (i18n) — 10 Languages with RTL Support

## Status
Accepted (2026-10-19, Pedro Belentani)

## Context

AION operates in ES, PT, FI, EU markets and needs 10 languages: Spanish (ES), English (EN), French (FR), German (DE), Italian (IT), Portuguese (PT), Chinese Simplified (ZH), Japanese (JA), Russian (RU), Arabic (AR). Arabic requires RTL support.

Options considered:
1. **react-i18next** — Mature, ICU message format, React integration
2. **next-intl** — Next.js specific, not Vite
3. **Custom Solution** — Lightweight but reinventing ICU, pluralization
4. **FormatJS + Custom Wrapper** — Standard, but verbose

## Decision

**We will use a custom lightweight i18n solution built on FormatJS/Intl with TypeScript-first dictionary files.**

### Current Implementation (Already in Codebase)

- `client/src/i18n.ts` (76KB) — Custom implementation
- Dictionary per language: `es.json`, `en.json`, `fr.json`, `de.json`, `it.json`, `pt.json`, `zh.json`, `ja.json`, `ru.json`, `ar.json`
- 34 Vitest tests passing
- RTL support via `dir` and `lang` attributes
- Regional date/time/currency formatting via `Intl.DateTimeFormat`, `Intl.NumberFormat`

### Architecture

```
client/src/
├── i18n.ts                 # Core: translations, locale detection, formatting
├── locales/
│   ├── es.json             # Spanish (source of truth)
│   ├── en.json
│   ├── fr.json
│   ├── de.json
│   ├── it.json
│   ├── pt.json
│   ├── zh.json
│   ├── ja.json
│   ├── ru.json
│   └── ar.json
└── components/
    └── LanguageSelector.tsx
```

### Key Features

1. **Type-Safe Keys** — TypeScript extracts keys from source locale
2. **Nested Namespaces** — `dashboard.metrics.totalHours`, `pvcu.risk.levels.L5`
3. **Pluralization** — ICU-style: `{count, plural, one {# hora} other {# horas}}`
4. **Regional Formatting** — `formatDate(date, locale)`, `formatCurrency(amount, locale, currency)`
5. **RTL Support** — `document.dir = locale === 'ar' ? 'rtl' : 'ltr'`
6. **Fallback Chain** — `ar → en → es` (graceful degradation)
7. **Persistence** — `localStorage` + cookie for SSR consistency

### Contract Enforcement

```typescript
// Contract test ensures no hardcoded strings in M/S features
test('i18n contract: no hardcoded strings in dashboard', () => {
  const dashboardFiles = glob('client/src/pages/Home.tsx');
  const hardcoded = findHardcodedStrings(dashboardFiles);
  expect(hardcoded).toHaveLength(0);
});
```

### Dynamic Content Localization

- **Enum values**: Roles, shift statuses, incident severities → localized via dictionary
- **API-driven**: PVC-U profiles, Open Data sources → localized descriptions
- **Event types**: Audit event types → localized labels
- **Technical data**: Hashes, IDs remain unlocalized (marked as technical evidence)

---

## Consequences

### Positive
- **Zero Runtime Dependencies**: No react-i18next bundle
- **Type Safety**: Missing keys caught at compile time
- **Performance**: Lazy-loaded dictionaries, tree-shaking
- **RTL Native**: `dir`/`lang` on `<html>`, CSS logical properties
- **Test Coverage**: 34 tests verify all 10 languages

### Negative
- **Maintenance Burden**: 10 dictionaries to keep in sync (mitigated: CI checks, translation workflow)
- **ICU Subset**: Custom pluralization not full ICU (mitigated: sufficient for our languages)
- **No Translation Management UI**: Developers edit JSON directly (mitigated: structured keys, PR reviews)
